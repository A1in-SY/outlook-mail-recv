# 修复收件箱返回当前页

## Goal

用户从账户列表的第 N 页进入某个账户的收件箱后，点击邮件页的“返回”应回到账户列表第 N 页，而不是重新落到第 1 页。

## Requirements

- 账户列表的当前页码必须可在路由跳转后恢复。
- 从账户列表进入收件箱或垃圾箱时，邮件页必须保留来源账户页码。
- 在收件箱与垃圾箱之间切换后，邮件页的“返回”仍回到原来源页。
- 没有有效来源页码时保持现有默认行为：返回账户列表第 1 页。
- 不修改后端 API、数据库、邮件页自身的分页或刷新语义。

## Acceptance Criteria

- [x] 在账户列表第 2 页或更后页面进入收件箱，点击“返回”后显示同一账户列表页码，并按该页码加载数据。
- [x] 从账户列表第 2 页或更后页面进入垃圾箱，点击“返回”后同样显示来源页码。
- [x] 进入一个邮件文件夹后切换到另一个文件夹，再点击“返回”，仍显示最初的账户列表页码。
- [x] 从第 1 页进入邮件页，或直接访问不含来源页码的邮件 URL，点击“返回”后显示账户列表第 1 页。
- [x] 无效、负数或非整数页码不会导致异常，并回退到第 1 页。
- [x] 本次涉及文件的 lint、前端全量测试与生产构建通过；全量 lint 不新增既有错误。

## Technical Approach

使用 URL 表示账户列表页码，并在进入邮件文件夹时携带来源页码。邮件页的“返回”显式导航到对应账户列表 URL；文件夹切换继续携带来源页码。页码解析采用有边界的纯函数，便于覆盖有效值和异常值。

## Decision (ADR-lite)

**Context**: 账户列表页码当前只保存在组件本地状态；进入邮件页后组件卸载，固定导航到 `/` 无法恢复来源页。

**Decision**: 使用路由可恢复的页码状态，而不是新增全局状态或持久化缓存。

**Consequences**: 返回行为可预测且刷新后仍能恢复页码；URL 会在非首页时包含页码参数。搜索、平台筛选和选择状态仍按现有行为重置。

## Out of Scope

- 保留账户列表的搜索词、平台筛选、勾选项、滚动位置或已打开弹窗。
- 改变邮件列表自身的分页、自动刷新或缓存行为。
- 引入全局状态库或新的浏览器端持久化机制。
- 调整后端、数据库或部署拓扑。

## Technical Notes

- `frontend/src/pages/AccountList.tsx` 当前用本地 `page` 状态加载账户，并直接导航到 `/emails/:accountId/:folder`。
- `frontend/src/pages/EmailList.tsx` 的“返回”当前固定调用 `navigate("/")`，文件夹切换也未携带来源页码。
- `frontend/src/App.tsx` 使用 React Router `BrowserRouter`；本任务保持现有路由结构。
- 前端规范明确可恢复的导航状态应放入 URL，且不应为页面局部工作流新增全局状态。
- 生产更新必须先只读识别 `txy-sg` 上的运行方式，再按现有进程或容器方式更新并验证。
